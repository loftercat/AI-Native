# 代码审查规则（Flutter 线，编码后、合并前的质量门禁）

> **规范听 Rule，流程听 Skill**：本规则定义 Flutter 线何时送审、审什么、分级、报告格式与闭环口径；编码流程见 [flutter-feature-coding](../skills/flutter-feature-coding/SKILL.md)。
> 与后端线代码审查规则同源；Flutter 线独立分发时以本文件为准，不跨线引用后端路径。
> 沿用前端 v2 的审查档位：按风险定档、L0 机械改动免审、单次审查、限时、最多 5 条 findings。

## 一、何时送审

- **触发点**：`flutter-feature-coding` 步骤 6 验证通过后、联调/提测前。
- **审查通过前禁止 commit / push**。
- **不送审**：L0 改动（文档、注释、格式化、重命名、目录/路径调整、构建描述符；不改运行时逻辑）；跑自动门禁并在回复说明。
- **审查人**：独立上下文（独立 AI 会话 / 审查 agent / 人），不复用实现会话；不绑定特定 Agent 工具。

## 二、档位选择

| 档位 | 适用改动 | 审查方式 | 闭环 |
|---|---|---|---|
| **L0 自动** | 文档、注释、格式化、重命名、目录/路径调整、构建描述符；不改运行时逻辑 | 不派 agent；自动门禁 + 人工抽查 diff | 自动门禁绿即可 |
| **L1 轻审** | ≤3 文件的小逻辑/配置改动，非本卡关键链路 | 一次只读审查，≤10 分钟，只看改动文件与直接依赖 | P0/P1 必修；P2 记录；P3 不报 |
| **L2 标准** | 一般功能改动（4–10 文件或单页面/单服务逻辑） | 一次只读审查，≤20 分钟 | P0/P1 必修；P2 中正确性/安全必修，其余记录；P3 不报 |
| **L3 深审** | 支付/订单/鉴权等核心链路页面、跨模块契约、破坏性存储迁移 | 一次只读审查，≤30 分钟，按 §四专项 | P0/P1/P2 必修；P3 记录；仅 P0/P1 触及核心逻辑时复审一次 |

- 涉及 OpenAPI 字段/错误码/契约语义变更不得用 L1。
- 实际改动明显超出所报档位 → 审查人立即指出并按更高档审查。
- 未注明档位时按 **L2** 执行。

## 三、送审输入（缺一不可）

| # | 输入 | 说明 |
|---|------|------|
| 1 | 审查档位 | L1 / L2 / L3 |
| 2 | 改动背景 | `STORY-Flutter-*` 编号、AC、不能破坏的行为 |
| 3 | 审查范围 | `git diff HEAD` + `git status` 中的**本次相关**新增未跟踪文件；或 `<base>..HEAD`；排除无关历史文件 |
| 4 | 上游工件 | `STORY-Flutter`、`DD-Flutter`、`docs/handoff/openapi/*.yaml`、`VERSION`（有则给） |
| 5 | 测试结果 | flutter analyze / flutter test、设备上的 AC 与设计对照结果 |
| 6 | 关注点 | 本次最担心的 3–5 项（operationId、字段契约、请求层、状态机、性能等） |

**审查任务书（跨 Agent 通用）**（复制后替换占位）：

```text
审查档位：L2
规则：从项目根读 AI-Native/flutter/rules/code-review.md（§二 档位 / §四 审查清单 / §五 P0–P3 与闭环）
改动背景：STORY-Flutter-...；AC：...；不能破坏：...
审查范围：git diff HEAD + git status 新增文件（本次相关；排除历史文件；重点：...）
上游工件：Story ...；DD-Flutter ...；OpenAPI ... @ VERSION ...
测试结果：分析和测试命令与结果；Android/iOS 证据；未验证项
关注点：...
只读：不修改仓库文件、不落盘报告
输出：按 P0–P3 附 path:line，最多 5 条；按 AI-Native/flutter/templates/code-review-report.md 输出档位、P0–P2 计数与结论（报告由实现者落盘）
```

> 这份任务书就是跨 Agent 的接口：任何独立审查人只要能读仓库并按此输出即可，不需要特定 Agent 或插件。

## 四、审什么

1. **契约**：只使用本卡 `operationId`；字段名/错误码只认 OpenAPI；不发明字段。
2. **请求层**：统一客户端处理认证、并发和幂等，Widget 将事件交给 ViewModel，由 ViewModel 经 Repository 访问业务数据。
3. **页面状态机**：加载、空、失败、成功对应 AC。检查过期响应、换号隔离及一次性事件。
4. **错误展示**：按契约映射用户反馈与恢复动作，避免泄露凭据或堆栈。
5. **性能**：局部重建、懒加载、图片解码、后台恢复，涉及 PlatformView 时检查视图释放。
6. **生命周期**：dispose 取消订阅与计时器；原生事件核对权限、取消与重复回调。
7. **测试**：分析与测试结果逐条对照 AC，记录本卡目标平台、设备及待验项。涉及存储、支付时验证迁移与服务端结果。
8. **可维护性**：组件边界、Dart 命名（包括业务 ViewModel）和重复实现，按档位记录。对照[中文业务注释写法](flutter-project.md#中文业务注释写法)核对本次变更。读页面和 Widget 注释应能在稿件或详设中找到对应区域；读工具注释应能判断调用结果；逐项核对 ViewModel 和状态类字段的注释与实际读写时机、界面表现是否一致。
9. **设计稿还原**：按 STORY-Flutter「设计稿」节逐项核对运行截图与交互状态，纯 UI 卡以此为重点。

按画像 §3.1 核对本卡使用的技术。

## 五、分级与闭环

| 级别 | 含义 | 处理 |
|------|------|------|
| **P0** | 错误结果、数据错误、安全/权限漏洞 | 必须修 |
| **P1** | 特定条件出错、边界未处理、明显契约错误 | 必须修 |
| **P2** | 性能问题、状态机缺陷、错误处理缺失 | 按 §二档位表 |
| **P3** | 命名、重复代码、可读性 | 按 §二档位表 |

- **L1**：P0/P1 必修；P2 记录；P3 不报。
- **L2**：P0/P1 必修；P2 中正确性/安全必修，其余记录；P3 不报。
- **L3**：P0/P1/P2 必修；P3 记录。
- **外部验证 P2**（真机/第三方确认等）：标「待确认」，记录平台、验证方式与负责人，按前端同档规则不阻塞审查。报告区分审查结论与尚待执行的真机验收。
- 修复后**不默认复审**；仅 L3 的 P0/P1 修复触及核心逻辑时复审一次；连续 2 轮不通过 → 交还人工。

## 六、报告

- **落点**：`docs/reviews/{迭代}/REVIEW-CODE-Flutter-{Story编号}-{slug}.md`
- **模板**：[code-review-report.md](../templates/code-review-report.md)
- **固定 footer**（由实现者/主流程按审查人输出落盘）：

  ```text
  - 审查档位：L2
  - P0：0
  - P1：0
  - P2：0
  - 结论：通过
  ```

- **结论「通过」** = 该档位闭环门槛满足；否则「不通过」。
- **重审**覆盖同名报告，轮次记在头部；历史轮次不另存。
- 审查人只读；**报告由实现者（主流程）落盘**。

## 七、与其他审查的区别

| 维度 | Story 审查 | 后端代码审查 | Flutter 端代码审查 |
|------|------------|--------------|--------------|
| 时机 | 拆卡后、详设前 | 编码后、合并前 | 编码后、联调/提测前 |
| 对象 | Story 卡 | 后端代码 diff | Flutter 端代码 diff |
| 分级 | Blocker/Major/Minor | P0–P3 | P0–P3 |
| 报告 | `REVIEW-STORY-*` | `REVIEW-CODE-*` | `REVIEW-CODE-Flutter-*` |

> 三者不能互相替代：Story 审查发生在代码之前；前后端代码审查各审各的 diff。
> Story 审查属后端线；Flutter 线不设 Story 审查门禁，本表仅用于区分审查对象。

## 八、跨 Agent 落地（不绑定工具）

- 只要求审查人独立、只读、能读取仓库与 diff；不绑定具体 Agent。
- 独立 AI 会话 / 专用审查 agent / 人 / CI 工具均可；任务书见 §三。
- 接入项目：把本规则与报告模板随 Flutter 线分发；在项目 `AGENTS.md` 增加「代码审查」节。

**Flutter 端项目 `AGENTS.md` 片段**：

```text
## 代码审查
Flutter 端代码改动（flutter-feature-coding 测试通过后、联调/提测前）必须走独立代码审查。
规则：AI-Native/flutter/rules/code-review.md；模板：AI-Native/flutter/templates/code-review-report.md；报告：在画像 §3.2 的应用根写 docs/reviews/{迭代}/REVIEW-CODE-Flutter-*。
审查通过前禁止 commit/push；L0 不送审；P0–P3 按 L1/L2/L3 闭环。
```
