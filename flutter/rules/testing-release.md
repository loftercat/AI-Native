# 测试、环境与发布

- 单测覆盖模型解析、Repository、状态转换与并发；Widget 测试通过 fake Repository 驱动输入、错误、重试和导航。集成测试走真实入口覆盖关键流程，平台插件另用设备验证。
- 应用 CI 按画像锁定 SDK 执行 pub get、所需代码生成、格式检查、flutter analyze、flutter test。集成测试指定目标设备，例如 flutter test integration_test/app_test.dart -d DEVICE_ID（替换为实际测试及设备）。记录 AC、命令、结果、平台与未验证项。
- 应用 PR 的基础检查依次运行 `dart format --output=none --set-exit-if-changed lib test`（按实际 Dart 源目录增补）、`flutter analyze`、`flutter test`，任一失败即报告失败。使用代码生成的模块在测试前按锁定版本重新生成；若项目提交生成文件，检查再生成后无意外差异。
- dev/staging/prod 用项目的 flavor、Xcode scheme 和环境配置隔离标识、接口、推送及统计。可读构建参数仅放公开配置，签名和服务端密钥在凭据系统维护。
- Android 校验目标变体的发布 AAB/APK、签名和混淆配置；iOS 在配置好 Xcode 的 macOS 上校验归档、签名和能力。模拟器无签名构建仅证明该目标能编译。
- 发布前两端核对最低支持版本与代表性真机，覆盖升级、旧库迁移、冷启动、断网、拒绝权限。保存构建号、提交、Dart 符号、Android 映射与 iOS dSYM（按实际构建产生）。正式环境的崩溃及业务指标脱敏并按版本区分。
- 分阶段发布观察崩溃、启动和核心业务成功率，明确停止扩量、关闭功能或发布修复的条件。旧客户端仍可能在线，后端继续兼容其契约。

## 分环境日志

由构建环境选择日志策略。即使用 release 模式打测试包，也使用测试策略。环境配置缺失时按正式策略处理。

| 环境 | 记录内容与查看方式 |
|---|---|
| 开发 | 真机日志页按时间查看网络、推送和 SDK 事件。测试服务的网络记录包含方法、路径、查询参数、请求头、请求体、响应状态、响应体、耗时与关联 ID，普通测试业务字段保留原值。推送记录注册、到达、点击和路由处理结果，以消息标识串联。SDK 初始化记录名称、版本、开始、成功或失败、耗时和错误码。二进制上传下载只记类型和大小，大报文截断并标明。 |
| 测试 | 控制台和真机日志页全量输出应用可获取的原始诊断信息。网络请求逐次记录方法、完整 URL、请求与响应的全部头和正文、状态、耗时、关联 ID，以及失败时的异常和堆栈。推送记录注册、接收、点击、路由结果及各阶段完整回调载荷。SDK 初始化记录名称、版本、入参、各阶段耗时、结果和原始错误详情。 |
| 正式 | 按事件白名单记录 SDK 关键生命周期结果（如初始化结果、推送注册失败）、应用未捕获异常和导致核心流程中断的失败。记录定位所需的版本、平台、阶段、错误码及脱敏关联 ID，异常可附清理后的堆栈。关闭网络明细、逐条推送、常规页面与状态跟踪、第三方 SDK 的调试输出，正式包不注册日志查看路由。 |

测试包所有字段按原值输出，包括 Authorization、Cookie、验证码、密码、推送设备令牌和个人信息。长报文按序号分段完整打印，二进制内容用可还原的编码分段输出。真机日志页及本地导出保留相同内容。

开发和正式环境的凭据与真实个人数据在进入日志系统前移除或遮盖，包括 URL、请求头、嵌套报文、推送载荷及异常文本里的令牌、Cookie、验证码、密码和推送设备令牌。控制台、内存历史、导出报告和崩溃事件沿用这一边界。

接入远程日志 SDK 时，从正式关键事件白名单生成结构化上传记录，测试明细只供本机排查。上传使用短期授权，隔离环境，异步发送并限制队列大小与重试次数。排除上传 SDK 自身的网络请求和重试日志，避免递归上报；上传失败时业务照常执行。

验收时用已知测试数据覆盖成功与失败请求、推送点击及 SDK 初始化失败。逐项对照控制台、真机日志页和本地导出中的头、正文、回调和凭据原值；拼接长报文及二进制分段后与输入逐字节比对。在正式包复测，确认日志页不可达、关键失败可定位，输出中没有请求或推送正文。
