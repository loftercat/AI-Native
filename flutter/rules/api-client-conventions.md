# 请求层与 OpenAPI Client 约束

## 1. 统一请求层

### 职责

从 [handoff](../docs/handoff/README.md) 的 OpenAPI + VERSION 确定 operationId、方法、路径、字段、分页、空值、时间单位及错误语义。仅调用本卡列出的公开服务。示例里的业务成功码仅适用于该契约。

Widget → Controller → Repository → Service → HTTP 客户端。每个信任域使用独立配置。统一 HTTPS、超时、请求关联 ID、取消和错误转换；业务 Token 仅向允许的主机发送，重定向也需校验目的地。生产构建验证证书。

### 骨架示例

```text
Controller → Repository → Service（operationId、DTO）
                        → 统一客户端（baseUrl、认证、超时、取消）
                        → 解析响应或抛出类型化错误
```

## 2. OpenAPI Client（可选）

### 生成

以 handoff 快照为输入，在 VERSION 变化后重新生成 Dart client，核对 operationId、空值和枚举。生成目录和命令由项目画像记录。

### 封装

Service 对应的 operationId、请求与响应字段均以当前 schema 为准。字段含义容易混淆时，可参考[工程规范](flutter-project.md)补中文说明。

Service 复用统一客户端，Repository 接收类型化数据。手写适配器时同样以已交接契约为准。

## 3. 鉴权流程

根据画像定义的认证失效信号处理 HTTP 401 或契约业务码。支持刷新时，同一会话的并发请求共享一次刷新；刷新端点排除自身拦截，原调用最多重放一次且请求体可重建。临时断网保留恢复机会，凭据确实失效时统一清会话并触发一次登录路由。退出或换号后丢弃旧会话的刷新结果和响应。

## 4. 错误展示

分别识别传输异常、HTTP 状态、业务结果与解析异常；兼容无响应体等契约约定。取消静默结束；超时可重试时给出入口；展示规则见[错误反馈](error-display-conventions.md)。

## 5. 多环境

Android flavor 与 iOS scheme 选择画像中对应的服务端环境。在构建时校验目标域名、签名和应用标识。敏感凭据存入安全存储。

## 6. 反模式

典型问题包括 Widget 直接拼接 URL、不同页面分别刷新 Token，以及切换账号后仍接受旧请求。

GET 等可安全重试的调用使用有限次数、退避并尊重服务端限流。创建、支付等写操作需要服务端幂等键及结果查询；响应丢失先确认结果。前端禁用按钮只能防止重复点击。

搜索防抖并校验请求序号；分页按查询条件、游标及账号隔离，拒绝过期页。上传另设超时与取消策略。日志仅保留操作名、状态、耗时与脱敏关联 ID。崩溃报告与错误埋点使用同一脱敏策略，验收时检查失败请求不会记录 Authorization、验证码或完整请求体。
