# 错误展示约束

## 1. 错误码分层

分别处理传输、HTTP、业务码、输入校验及平台 SDK 错误。判据与字段以画像及本次 handoff 为准。

## 2. 展示方式

由请求层/平台适配层归类失败，Controller 生成恢复动作，View 按 AC 呈现。后端明确面向用户的 message 可按契约使用，其余使用本地化文案。异常堆栈、响应正文、凭据和个人信息不进入界面。

| 情形 | 展示与恢复 |
|---|---|
| 初次加载失败 | 页面错误态 + 重试按钮 |
| 刷新或翻页失败 | 保留当前内容，列表顶部或尾部给出重试 |
| 搜索无匹配 | 空态，保留关键词 |
| 输入校验失败 | 字段旁提示，保留输入并聚焦需修改处 |
| 一次操作失败 | 局部提示或 SnackBar，由用户明确重试；需用户决策再用 Dialog |
| 凭据失效 | 会话层统一通知路由，页面结束 loading；登录恢复时重新验证目标 |
| 权限被拒 | 解释受影响功能，提供替代输入或系统设置入口 |
| 取消 / 过期结果 | 恢复可操作状态，取消动作本身无需报错 |

## 3. 文案来源

契约约定可展示的 message 可直接使用。需本地化时按错误类型统一映射，日志与 UI 分开处理。

## 4. 全局拦截

认证过期交给会话层恢复，路由统一响应登录状态变化。取消和迟到的响应由请求所有者处理。

## 5. 反模式

一次提交最多一次提示；Widget 重建、回到前台、多个请求同时失败时避免重复弹窗。支付等结果不明确时展示确认中并查询订单。
