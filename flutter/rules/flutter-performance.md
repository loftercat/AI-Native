# Flutter 性能与内存约束

## 1. 状态更新与 Widget 重建

状态监听缩到需要刷新的子树。倒计时用截止时间减当前时间，前台恢复时重新计算；停止不可见动画，避免定时回调驱动整页刷新。

## 2. 资源释放与内存泄漏

所有者释放 AnimationController、FocusNode、TextEditingController、Timer 和 StreamSubscription。页面退出时取消只服务本页的请求；异步返回写界面前检查 mounted 和当前请求标识。

切后台、页面被遮盖、Widget dispose 和系统杀进程是不同事件。草稿在编辑时保存，恢复前台时对齐会话、订阅和数据新鲜度。

## 3. 渲染性能

长列表按需构建、分页，列表项用稳定业务 ID 标识。按目标显示尺寸解码图片并限制缓存。大 JSON 或计算先测量，再决定是否移到 isolate。

## 4. 启动与包体积

地图等 PlatformView 测试首次展示、手势冲突、进出多次后的纹理与监听器释放。启动记录首个可操作页面耗时，将可延迟的 SDK 初始化移出关键路径。 对比同一目标架构、flavor 与构建模式的发布包，按实际贡献检查新增资源或 SDK。

## 5. 网络与缓存

搜索和分页按输入合并请求，拒绝迟到结果。图片与数据缓存按账号、容量和过期条件清理。详见[状态与存储](state-storage-events.md)。

## 6. 性能评测

在目标设备的 profile 构建复现卡顿，用 DevTools 分别观察 UI 和 raster 耗时、重建范围及内存曲线，按设备刷新率和画像中的预算判定。记录操作、设备、基线及改动后测量。

## 7. 反模式

把 I/O 放进 build、用全屏重建驱动局部动画、后台仍持续刷新地图或倒计时，都应在性能自检中排查。
