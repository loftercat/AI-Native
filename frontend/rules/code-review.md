# 代码审查规则（前端线，编码后、合并前的质量门禁）

> **规范听 Rule，流程听 Skill**：本规则定义前端线何时送审、审什么、分级、报告格式与闭环口径；编码流程见 [frontend-feature-coding](../skills/frontend-feature-coding/SKILL.md)。
> 与后端线代码审查规则同源；前端线独立分发时以本文件为准，不跨线引用后端路径。
> 同源版本：v1（2026-11-12）；修改 P0–P3 表、闭环门槛、报告 footer 或轮次上限时，必须同步后端线代码审查规则。

## 一、何时送审

- **触发点**：`frontend-feature-coding` 步骤 6 验证通过后、联调/提测前。
- **审查通过前禁止 commit / push**。
- **不送审**：L0 改动（纯注释、格式化、重命名、日志/文案字符串）；在回复中说明跳过原因。
- **审查人**：独立上下文（独立 AI 会话 / 审查 agent / 人），不复用实现会话；不绑定特定 Agent 工具。

## 二、档位选择

| 档位 | 适用改动 | 审查深度 | 闭环门槛 |
|------|----------|----------|----------|
| **L1 轻审** | ≤2 文件的小增量、非本卡关键链路；单个配置常量的值调整 | 只查正确性：空值/边界、明显逻辑错误、异常被吞、明显契约错误 | P0/P1 必须修；P2 记录不阻塞（最多 1–2 条）；P3 不报 |
| **L2 标准**（默认） | 3–8 文件，或单页面/单服务的逻辑变更 | 完整流程；按改动背景与关注点逐条回应 | P0/P1/P2 必须修；P3 酌情 |
| **L3 深审** | 支付/订单/鉴权等核心链路页面、跨模块、>8 文件或 diff >400 行 | 完整流程 + 专项清单：状态机、契约兼容、性能、生命周期、错误恢复 | P0–P3 全部闭环 + 复审确认 |

- 涉及 OpenAPI 字段/错误码/契约语义变更不得用 L1。
- 实际改动明显超出所报档位 → 审查人立即指出并按更高档审查。
- 未注明档位时按 **L2** 执行。

## 三、送审输入（缺一不可）

| # | 输入 | 说明 |
|---|------|------|
| 1 | 审查档位 | L1 / L2 / L3 |
| 2 | 改动背景 | `STORY-FE-*` 编号、AC、不能破坏的行为 |
| 3 | 审查范围 | `git diff HEAD` + `git status` 中的**本次相关**新增未跟踪文件；或 `<base>..HEAD`；排除无关历史文件 |
| 4 | 上游工件 | `STORY-FE`、`DD-FE`、`docs/handoff/openapi/*.yaml`、`VERSION`（有则给） |
| 5 | 测试结果 | `npm test`（jest）结果、开发者工具关键 AC 手测结果 |
| 6 | 关注点 | 本次最担心的 3–5 项（operationId、字段契约、请求层、状态机、性能等） |

**审查任务书（跨 Agent 通用）**（复制后替换占位）：

```text
审查档位：L2
规则：先读 rules/code-review.md（§二 档位 / §四 审查清单 / §五 P0–P3 与闭环）
改动背景：STORY-FE-...；AC：...；不能破坏：...
审查范围：git diff HEAD + git status 新增文件（本次相关；排除历史文件；重点：...）
上游工件：Story ...；DD-FE ...；OpenAPI ... @ VERSION ...
测试结果：npm test 通过；手测 AC-...
关注点：...
只读：不修改仓库文件、不落盘报告
输出：按 P0–P3 附 path:line；按 templates/code-review-report.md 的六行格式输出档位、P0–P3 计数与结论（报告由实现者落盘）
```

> 这份任务书就是跨 Agent 的接口：任何独立审查人只要能读仓库并按此输出即可，不需要特定 Agent 或插件。

## 四、审什么

1. **契约**：只使用本卡 `operationId`；字段名/错误码只认 OpenAPI；不发明字段。
2. **请求层**：页面不直接 `wx.request`；统一走 `services/` / `api/http.js`；401 与 `body.code` 统一处理。
3. **页面状态机**：加载/空/失败/成功状态齐全；分支与 AC 对应。
4. **错误展示**：错误码→用户文案映射完整；不吞错误、不展示技术堆栈。
5. **性能**：`setData` 合并/低频/单次大小；长列表分页/虚拟列表；倒计时不 `setInterval` + 高频 `setData`。
6. **生命周期**：`onUnload` 解绑 `wx.on*`、清定时器、清全局引用。
7. **测试**：jest 覆盖 `services/`/纯逻辑；页面关键 AC 有手测记录；无跳过。
8. **可维护性**：组件边界、重复代码、命名（P3 酌情）。

## 五、分级与闭环

| 级别 | 含义 | 处理 |
|------|------|------|
| **P0** | 错误结果、数据错误、安全/权限漏洞 | 必须修 |
| **P1** | 特定条件出错、边界未处理、明显契约错误 | 必须修 |
| **P2** | 性能问题、状态机缺陷、错误处理缺失 | L1 记录；L2/L3 必须修 |
| **P3** | 命名、重复代码、可读性 | L1 不报；L2 酌情；L3 闭环 |

- **L1**：P0/P1 清零；P2 记录不阻塞（最多 1–2 条）；P3 不报。
- **L2**：P0/P1/P2 清零；P3 酌情。
- **L3**：P0–P3 全部闭环 + 复审确认。
- **外部验证 P2**（真机/第三方确认等）：标「待确认」，写明验证方式，不阻塞；但必须记录。
- 审查人**只读**；实现者修复后重派，报告同名覆盖、轮次 +1；连续 >3 轮不通过 → 交还人工。

## 六、报告

- **落点**：`docs/reviews/{迭代}/REVIEW-CODE-FE-{Story编号}-{slug}.md`
- **模板**：[code-review-report.md](../templates/code-review-report.md)
- **固定 footer**（由实现者/主流程按审查人输出落盘）：

  ```text
  - 审查档位：L2
  - P0：0
  - P1：0
  - P2：0
  - P3：0
  - 结论：通过
  ```

- **结论「通过」** = 该档位闭环门槛满足；否则「不通过」。
- **重审**覆盖同名报告，轮次记在头部；历史轮次不另存。
- 审查人只读；**报告由实现者（主流程）落盘**。

## 七、与其他审查的区别

| 维度 | Story 审查 | 后端代码审查 | 前端代码审查 |
|------|------------|--------------|--------------|
| 时机 | 拆卡后、详设前 | 编码后、合并前 | 编码后、联调/提测前 |
| 对象 | Story 卡 | 后端代码 diff | 前端代码 diff |
| 分级 | Blocker/Major/Minor | P0–P3 | P0–P3 |
| 报告 | `REVIEW-STORY-*` | `REVIEW-CODE-*` | `REVIEW-CODE-FE-*` |

> 三者不能互相替代：Story 审查发生在代码之前；前后端代码审查各审各的 diff。
> Story 审查属后端线；前端线不设 Story 审查门禁，本表仅用于区分审查对象。

## 八、跨 Agent 落地（不绑定工具）

- 只要求审查人独立、只读、能读取仓库与 diff；不绑定具体 Agent。
- 独立 AI 会话 / 专用审查 agent / 人 / CI 工具均可；任务书见 §三。
- 接入项目：把本规则与报告模板随前端线分发；在项目 `AGENTS.md` 增加「代码审查」节。

**前端项目 `AGENTS.md` 片段**：

```text
## 代码审查
前端代码改动（frontend-feature-coding 测试通过后、联调/提测前）必须走独立代码审查。
规则：rules/code-review.md；模板：templates/code-review-report.md；报告：docs/reviews/{迭代}/REVIEW-CODE-FE-*。
审查通过前禁止 commit/push；L0 不送审；P0–P3 按 L1/L2/L3 闭环。
```
