# 代码审查规则（轻量版）

> 目标：只花必要的时间挡住会出错的改动；机械改动交给构建、测试与链接校验。
> 同源版本：v2（2026-11-13）。替代 v1 的「按文件数升档」「L3 全 P 闭环 + 必复审」。

## 一、先跑自动门禁（不过不送审）

- 后端：`mvn test`（或等价）全绿。
- 工作流资产：`bash backend/scripts/validate-skills.sh` PASSED（模板根）。
- 文档/路径改动：相对链接 0 断链。
- 前端：lint + test 全绿。
- 自动门禁已覆盖的编译、单测、链接、格式，审查人不再重复检查。

## 二、档位（按风险，不按文件数）

| 档位 | 适用改动 | 审查方式 | 闭环 |
|---|---|---|---|
| **L0 自动** | 文档、注释、格式化、重命名、目录/模块移动、路径替换、构建描述符调整；不改运行时逻辑 | 不派 agent；跑自动门禁 + 人工抽查 diff | 自动门禁绿即可 |
| **L1 轻审** | ≤3 文件的小逻辑/配置/脚本改动，非核心链路 | 一次只读审查，≤10 分钟，只看改动文件与直接依赖 | P0/P1 必修；P2 记录；P3 不报 |
| **L2 标准** | 一般功能改动（4–10 文件或单模块逻辑） | 一次只读审查，≤20 分钟 | P0/P1 必修；P2 中正确性/安全必修，其余记录；P3 不报 |
| **L3 深审** | 资金/支付/订单/鉴权/权限/事务/并发/幂等、DDL/批量数据、跨模块契约 | 一次只读审查，≤30 分钟，按 §四专项 | P0/P1/P2 必修；P3 记录；仅 P0/P1 触及核心逻辑时复审一次 |

- **同一批改动只审一次**，按最高风险档；不要拆成多次审。
- **机械改动不因文件数升档**：跨 100 个文件的移动/改名仍是 L0。
- **拿不准时选低一档 + 自动门禁补强**；只有核心链路/契约才升 L3。
- 纯配置常量值调整：L1；改接口语义/契约：至少 L2。

## 三、送审输入（最小集）

1. 档位。
2. 改动目的 + 不能破坏的行为（Story/Bug/AC）。
3. 变更文件清单（`git diff --stat` / `git status -uall`；无基线时显式列出）。
4. 自动门禁结果。
5. 最担心的 1–3 个点。

审查人只看变更文件与直接依赖，不通读全仓；缺输入时先问，不猜。

## 四、审什么（按档位取用）

- **L1**：正确性、边界、异常、是否改变既有行为、测试是否覆盖改动。
- **L2**：L1 + 分层/依赖方向、事务/幂等/并发、错误码/契约一致性、安全与权限。
- **L3**：L2 + 数据迁移/回滚、兼容性、性能/资源、跨模块调用链。
- 不审命名、格式、重复代码（P3）；除非已影响可维护性。
- 场景补充只取相关项：IT 看真实 HTTP/DB、Mock 边界、隔离清理；BB/SEED 看 Token/URL 不硬编码、不接生产、seed 幂等、反序清理。

## 五、P0–P3 与闭环

- P0：错误结果、丢数据、安全漏洞。
- P1：特定条件出错、边界未处理、资源泄漏。
- P2：性能、明显设计缺陷、异常处理缺失。
- P3：命名、重复、可读性。

闭环：

- L1：P0/P1 必修；P2 记录；P3 不报。
- L2：P0/P1 必修；P2 中正确性/安全必修，其余记录；P3 不报。
- L3：P0/P1/P2 必修；P3 记录。
- 外部验证 P2 标「待确认 + 验证方式」，记录不阻塞。
- 修复后**不默认复审**；仅 L3 的 P0/P1 修复触及核心逻辑时复审一次。
- 连续 2 轮不通过 → 交还人工。

## 六、输出

- 审查人只读，不修文件；最多 5 条 findings，按 P0–P3 排序。
- 每条：`文件:行` + 问题 + 建议。
- 结论一行：`档位 / P0 / P1 / P2 / 结论`。
- L1+ 报告落 `docs/reviews/{迭代}/REVIEW-CODE-{阶段}-*.md`，模板见 [code-review-report.md](../templates/code-review-report.md)。
- L0 不落报告；在回复或提交说明写「L0 + 自动门禁结果」。

## 七、跨 Agent

- 独立上下文、只读、能读 diff 即可；不绑定 Agent/插件。
- 审查任务书直接用 §三；报告由实现者落盘。
