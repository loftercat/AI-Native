# 用例归一化指引（case-normalize-guide）

> 配套 [legacy-test-migration SKILL](../SKILL.md) Step 1。
> 目标：把「只有中文/自由文本」的存量用例，归一化为**可判定**的 Given/When/Then 记录，且**不改原文**。

## 1. 归一化产物结构

```yaml
legacy_tc_id: TC-0001        # 原编号，不改
title: 查询车位-正常返回       # 摘要（展示列）
source_text: |               # 原文片段（保留，供回溯）
  ...
given: ...                   # 前置条件
when: ...                    # 操作步骤（触发动作）
then:                        # 预期结果（可多条）
  - ...
anchor_hint: 车位查询接口      # 业务对象/动作，供 Step 4 锚定
missing: []                  # 缺失字段
```

## 2. 结构映射规则

| 存量常见段落 | 目标 | 规则 |
|--------------|------|------|
| 前置条件 / 环境 / 数据准备 | Given | 数据依赖保留为 Given 子项 |
| 操作步骤 / 执行 / 输入 | When | 多步合并为一次「触发」；参数不同视为参数化 |
| 预期结果 / 校验点 / 断言 | Then | **每条可判定预期拆为一个 Then** |
| 备注 / 关联需求 | — | 保留到 `source_text`，不参与判定 |

## 3. Then 可判定性检查

- 可判定：含具体值/状态/文案/HTTP 码（如「返回 code=200 且 list 非空」）
- 不可判定：含「正常」「正确」「无异常」等模糊词 → 标 `missing` 并要求补具体值
- 模糊 Then 数量 > 0 且无法补齐 → `gate=G1`（见分类指引 §2）

## 4. 缺失与矛盾处理（不猜）

| 情况 | 处理 |
|------|------|
| 无预期结果 | `missing += then`，`gate=G1`，`blocker=缺预期结果` |
| 有预期但含模糊词 | `missing += then 具体值`，**不猜**，倾向 `G1` |
| 步骤与预期矛盾 | `blocker=步骤与预期矛盾（{点}）`，`gate=G1` |
| 无前置条件但可推断 | 记 `given=（原文未给，下游补）`，不阻断 |

## 5. 数据依赖标注

- 归一化时识别用例的数据需求（如「存在 ENABLED 车场」）→ 保留在 Given。
- 下游交 `test-data-design` 时用 `seed_key` 命名（见 `test-data-design` Skill）。

## 6. 反模式（禁止）

- ❌ 把「预期结果」改写成 AI 自己认为对的值（改写 = 引入新基准）
- ❌ 把多条独立预期合并为一条（丢失可判定粒度）
- ❌ 丢弃原文（必须保留 `source_text` 供回溯）
- ❌ 在归一化阶段就判层（分层是 Step 3，归一化只做 GWT）

## 7. Few-shot

原文：
```
前置：测试环境有 ENABLED 车场「万象城」，含 1 个 AVAILABLE 车位
步骤：小程序搜索「万象城」并发起预约
预期：预约成功，返回订单号
```

归一化：
```yaml
legacy_tc_id: TC-0001
title: 搜索车场并发起预约
given: 存在 ENABLED 车场「万象城」+ ≥1 AVAILABLE 车位
when: 搜索「万象城」并提交预约
then:
  - 预约成功
  - 返回订单号非空
anchor_hint: 预约下单接口
missing: []           # 「成功」的具体 code 待补 → 若下游要求可标 G1
```
