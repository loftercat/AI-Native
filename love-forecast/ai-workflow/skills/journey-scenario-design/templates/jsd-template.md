## 3. 业务场景清单（Scenario Matrix）

> **管深度**：每场景一行，统一用「前置条件 + 触发 + 预期结果」描述（同 BDD/Gherkin 的 Given / When / Then）。编号 `SC-{旅程}-{序号}`（如 SC-J1-03），**须回链阶段编号**。

### 3.0 场景生成方法（按业务复杂度选择）

> 因子建模与「前置条件 + 触发 + 预期结果」**不是二选一，是流水线两步**：因子建模回答「**该有哪些场景**」（枚举、防遗漏）；GWT 回答「**每个场景长什么样**」（描述、可验证）。复杂业务先建模、再描述；简单业务跳过建模、直接描述。

| 业务复杂度 | 判定标准 | 场景生成方式 |
|------------|----------|--------------|
| 简单 | 正交变化维度 ≤ 2，且同一动作不随角色/对象/情境改变规则 | **跳过因子表**：每阶段写主场景，按 [scenario-branch-checklist.md](../references/scenario-branch-checklist.md) 逐维度扫描补备选/异常，直接落入 §3.1 |
| 复杂 | 正交因子 ≥ 3，或同一动作在不同因子取值下**业务规则不同**（典型 B 端：多角色 × 多对象 × 多情境） | 先填下方因子表 → 差异驱动挑代表组合 → **每个组合展开为 §3.1 的一行 GWT 场景** |

> **防爆炸规则**：因子组合**差异驱动**——仅当组合的业务规则不同才派生场景，不做全笛卡尔积；组合数 > 20 时取代表组合（每个因子取值至少被一个场景覆盖）。

**因子表**（仅复杂业务填写；取值示例为格式示意，按目标项目领域填写）：

| 因子编号 | 因子（类别：角色/业务对象/情境） | 说明 | 取值（枚举） |
|----------|----------------------------------|------|--------------|
| F1 | 角色（格式示例：会员 / 企业客户 / 代理人） | | |
| F2 | 业务对象（格式示例：标准版 / 增值版 / 定制版） | | |
| F3 | 情境（格式示例：渠道——线上 / 线下；时段——即时 / 预约） | | |

代表性组合（差异驱动，仅列规则不同的组合）：

| 组合编号 | 因子取值 | 业务规则差异 | 派生场景 |
|----------|----------|--------------|----------|
| C1 | F1=会员 × F2=标准版 × F3=即时 | 基准规则 | SC-J1-01 |
| C2 | F1=企业客户 × F2=增值版 × F3=预约 | 规则不同：… | SC-J1-05 |
