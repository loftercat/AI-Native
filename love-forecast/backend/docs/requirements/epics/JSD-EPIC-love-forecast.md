## 1. 角色与目标（Persona）

| 编号 | 角色 | 端 | 目标（想完成什么） | 痛点 / 动机 |
|------|------|----|--------------------|-------------|
| P1 | **求助者**（注册用户） | C 端 Web | 在不知道该回什么的时候，拿到一条能发得出去的话 | 现有话术库不区分对象；问朋友难以启齿；通用 AI 每次都要重新交代背景 |
| P2 | **关系对象**（非注册用户） | — | —（不登录、不感知） | 仅以沟通记录与行为观察集的形式存在；是数据主体，不是用户 |
| P3 | 运营管理员 | B 端 | MVP 不建 | 内容安全靠规则 + 模型双层校验，不靠人工审核台 |

**角色前提**（来自画像 §一）：

- P1 是唯一登录角色；所有数据按 `userId` 隔离。
- P2 不可访问系统，产品内无法行使权利；删除与导出通道面向 P1 提供。
- 不要求 P2 同意，采用用户单方授权 + 充分告知（PRD §10.2）。

## 2. 用户旅程（Journey Map）

### 2.1 旅程 J1：首次求助——不知道回什么，拿到三档建议（主旅程）

| 阶段编号 | 阶段 | 角色 | 用户行为 | 系统响应（本仓库侧） | 触点 | 断点/痛点 |
|----------|------|------|----------|----------------------|------|-----------|
| J1.1 | 进入与登录 | P1 | 从落地页进入，注册或登录 | 签发 JWT；登录后返回档案列表（空列表给引导） | Web | 首次无档案时容易迷路 |
| J1.2 | 建关系档案 | P1 | 填对方代号、关系类型、关系状态 | `ProfileApi` 创建档案；校验数量上限（3）与必填 | Web | 用户可能填真名，需提示用代号 |
| J1.3 | 说清情境 | P1 | 用自己的话描述发生了什么、对方最后说了什么、想达到什么 | `AdviceApi` 解析情境与诉求类型；信息不足时现场追问（≤5 轮）；识别到危机信号则中止 | Web | 描述过短会导致建议泛化 |
| J1.4 | 拿三档建议 | P1 | 查看稳妥 / 共情 / 直给三条建议 | 策略合成 → 话术生成 → 越界校验；每条带依据、前提、风险、失效条件；页面标注「本次未使用历史记录，个性化程度有限」 | Web | 三档同时给出，用户可能只想要一条 |
| J1.5 | 可选演练 | P1 | 试着说出自己想说的话，看 AI 扮演的对方如何回应 | 以对方口吻回应；每轮附 1–3 种假设性解读；单次 ≤10 轮；固定标注 AI 模拟 | Web | 可能把模拟当成对方真实态度 |
| J1.6 | 标记与复制 | P1 | 复制某条建议，标记采纳 / 未采纳 / 自己改了 | 记录采纳三态；复制为纯文本，不含系统标注 | Web | 复制出去后系统无法感知实际效果 |
| J1.7 | 可选沉淀 | P1 | 觉得有用，选择「让建议更准」并补入历史记录 | 跳转导入页；导入完成后提示「已补入 N 条样本，观察集已更新」；返回工作台时取消「个性化程度有限」提示 | Web | 需要用户有动力补数据；补入后建议质量提升不明显会流失 |

```text
登录 → 建档 → 说情境 → 拿建议 → 可选演练 → 复制/采纳 → 可选沉淀（补记录）
```

**关于建议与演练的顺序**：JSD 按「先给建议、可选演练」组织，与 PRD §7.2（先模拟后建议）不同，采用 PRD §7.4「三栏同屏、非严格线性」的解释。该差异记入 §6 开放问题。

| 阶段编号 | 阶段 | 角色 | 用户行为 | 系统响应（本仓库侧） | 触点 | 断点/痛点 |
|----------|------|------|----------|----------------------|------|-----------|
| J2.1 | 导入记录 | P1 | 从工作台或档案页点「让建议更准」，勾选授权告知，粘贴聊天文本 | `ProfileApi` 校验授权、文本长度、敏感信息；提示样本量 | Web | 用户可能跳过授权告知 |

| J2.3 | 查看观察集 | P1 | 打开档案详情，看三档观察 | 只输出可复算的计数与原句；每条结论按四段式展示：观察 / 本样本充分性 / 理论证据强度 / 不可推断声明 | Web | 可输出档只有结构量，用户可能觉得「没分析」 |
| J2.4 | 描述情境 | P1 | 填三要素 | 结构化解析；缺失时追问 ≤2 轮 | Web | — |
| J2.5 | 拿建议 | P1 | 查看基于观察的建议 | 观察检索 → 策略合成 → 话术生成 → 校验；依据指回观察条目 | Web | 观察为空时须退化为现场描述模式并提示 |
| J2.6 | 回填反馈 | P1 | 标记采纳，事后回填对方真实反应 | 写入档案记忆（结构化条目，不存整段对话）；记忆条目在记忆页可见 | Web | 用户常不回填，效果信号稀少 |

```text
导入 → 标注 → 看观察集 → 描述情境 → 拿建议 → 回填
```

## 3. 业务场景清单（Scenario Matrix）

### 3.0 场景生成方法

**判定：简单业务，跳过因子表。**

理由：角色单一（仅 P1 登录）、同一动作不随角色改变规则；「有无历史记录」这一主要变化维度已由 J1 / J2 两条旅程分开承载，不再需要用因子组合派生。关系状态（甜蜜/冷战/濒危）只影响建议策略参数，不改变系统流程走向，故不作为场景因子。

**双模式输入已由旅程承载**：现场描述模式 = J1，结构化模式 = J2，不需要额外场景。
