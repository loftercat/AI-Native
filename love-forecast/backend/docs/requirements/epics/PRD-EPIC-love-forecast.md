## 1. 一句话定义

**在你不知道该怎么回另一半的时候，先读懂对方，再演练一遍，然后发出去。**

用户把与另一半的历史沟通记录交给系统，系统分析对方的沟通人格，扮演对方与用户模拟对话，并给出当下最合适的回复建议。

---

## 2. 背景与问题

### 2.1 真实场景

> 晚上 11 点，对方发来一句「哦，随便你吧」。
> 你不知道这是真的随便，还是在生气；不知道回「好」会不会更糟，回长文会不会显得卑微。
> 你打开搜索引擎搜「女朋友说随便你吧怎么回」，得到一堆通用话术——**但没有一句是为你眼前这个人写的**。

### 2.2 现有方案为什么不够

| 方案 | 问题 |
|------|------|
| 搜索引擎/话术库 | 通用话术，不区分对象；越搜越焦虑 |
| 朋友求助 | 朋友不了解对方；且涉及隐私难以启齿 |
| 通用 AI 对话 | 每次都要重新交代背景；没有对「这个人」的持续记忆；给的建议是同质化的 |
| 情感咨询 | 贵、慢、门槛高；不适合「今晚就要回」的即时场景 |

### 2.3 本产品的解法

**个体化 + 记忆 + 演练。**

- **个体化**：建议基于「这个具体的人」的沟通模式，不是通用话术
- **记忆**：对方的画像、历史情境、你采纳过什么、对方真实反应如何，持续沉淀
- **演练**：先跟 AI 扮演的对方试说一遍，看到可能的反应，再决定发什么

---

## 3. 产品定位与价值主张

### 3.1 定位

**亲密关系沟通辅助工具**，不是情感咨询、不是话术库、不是恋爱技巧培训。

### 3.2 价值主张

| 对用户 | 价值 |
|--------|------|
| 即时性 | 今晚就要回，3 分钟内拿到可执行的建议 |
| 个体化 | 建议是「对这个人」的，不是「对所有人」的 |
| 低风险 | 先演练，避免说错话把关系推向更糟 |
| 成长性 | 用得越久，系统越懂你们的关系模式 |

### 3.3 不做的事（定位边界）

- 不教「如何让对方离不开你」这类操控技巧
- 不替代心理咨询与治疗
- 不做「测谎」「忠诚度检测」
- 不做自动代聊（不代替用户发送消息）

## 4. 目标用户

### 4.1 主角色

| 编号 | 角色 | 描述 | 核心诉求 |
|------|------|------|----------|
| P1 | **求助者**（C 端注册用户） | 处于亲密关系中，遇到沟通卡点，不知道如何回复 | 快速拿到「能发出去」的回复 |
| P2 | **关系对象**（非注册用户） | 用户的另一半。只以「沟通记录 + 行为观察集」的形式存在于系统中，不登录、不感知 | —（数据主体，非用户） |
| P3 | **运营管理员**（内部，MVP 不建） | 内容安全审核、异常处置 | — |

> **P2 的特殊性**：P2 是数据主体但不是用户，无法行使产品内的权利。这是本产品最大的合规与伦理约束来源，见 §9。

### 4.2 用户画像（假设，待验证）

| 维度 | 假设 |
|------|------|
| 年龄 | 22–35 岁 |
| 关系状态 | 恋爱中 / 已婚 / 暧昧期 / 分手挽回期 |
| 典型触发 | 冷战、争吵后、对方情绪低落、自己说错话、不知道怎么拒绝、异地 |
| 使用频次 | 关系平稳期低频，冲突期高频（可能一天多次） |
| 付费意愿 | 本期不做商业化，不设付费点；仅记录为后续可能的验证方向 |
| 使用成本 | 单次建议生成涉及多次模型调用，无收入侧约束，需要对调用次数设软上限 |

## 5. 核心概念与领域模型

> 这些名词将进入 `glossary/domain-glossary.md`，是后续 JSD / HLD / Story 的共同语言。

| 概念 | 定义 | 与谁相关 |
|------|------|---------|
| **关系档案**（Relationship） | 一段关系 = 一个对象。包含对方人格画像、沟通记录、历史会话 | 属于 P1 |
| **人格画像**（Persona Profile） | 产品对外名称；技术上是**可复算的行为观察集**：消息节奏、话轮结构、回应性行为、词频。**不含**特质分数、类型标签、需求推断 | 属于关系档案 |
| **沟通样本**（Conversation Sample） | 用户导入的原始聊天记录（文本） | 属于关系档案 |
| **情境**（Situation） | 一次求助的上下文：发生了什么、对方最后说了什么、用户想达到什么 | 属于会话 |
| **模拟对话**（Simulation） | AI 以对方口吻回应，供用户演练 | 属于会话 |
| **回复建议**（Reply Suggestion） | 1–3 条候选话术，带适用前提与风险提示 | 属于会话 |
| **反馈**（Feedback） | 用户是否采纳、对方真实反应如何 | 回流到关系档案的记忆 |

**层级关系**：

```text
用户 (P1)
└── 关系档案 (1..3 个)
    ├── 人格画像 (1)
    ├── 沟通样本 (n)
    └── 会话 (n)
        ├── 情境 (1)
        ├── 模拟对话 (n 轮)
        ├── 回复建议 (1..3 条)
        └── 反馈 (0..1)
```

## 6. 目标与非目标

### 6.1 目标（MVP）

| # | 目标 | 判定标准 |
|---|------|----------|
| G1 | 用户能把聊天记录交给系统并得到分级画像 | 按规范三档输出；可输出档为行为计数，推断档必须带证据强度与不可推断声明 |
| G2 | 用户能演练并拿到可发出去的回复 | 每轮给出 ≥3 条候选，带适用前提与风险 |
| G3 | 用户数据完全隔离 | 任何跨用户访问均不可达 |
| G4 | 会话具备记忆 | 同一档案下新会话能复用画像与历史反馈 |
| G5 | 产品不越伦理边界 | 安全规则命中时拒绝生成并转介 |

### 6.2 非目标（MVP 明确不做）

- 截图 OCR 导入（V1）
- 语音消息分析
- 自动发送到微信/其他 IM
- 多人关系（三角关系、家庭群）
- 恋爱匹配 / 相亲
- 心理诊断、依恋类型定性结论
- 社区、动态、匿名倾诉
- 对方侧的任何客户端
- 情感咨询师撮合 / 人工服务
- **商业化：付费、订阅、额度售卖、增值服务**（本期只做防滥用限流，不做商业分层）

## 7. 用户旅程

**两条入口，一个工作台**：首用走 J1-A（现场描述，不依赖历史），进阶走 J1-B（导入记录，个性化更强）。两条都汇入同一工作台，不存在「必须攒够记录才能用」的门槛。

### 7.1 主旅程 J1-A：首次使用（现场描述，2 分钟内交付价值）

| 阶段 | 用户行为 | 系统响应 | 触点 |
|------|----------|----------|------|
| J1-A.1 进入 | 从落地页了解产品，注册 / 登录 | 一句话价值 + 数据用途告知；登录后进入档案列表 | Web |
| J1-A.2 建档 | 创建关系档案：对方昵称（可用代号）、关系类型、关系状态 | 校验并落库；提示「建议不要用真名」 | Web |
| J1-A.3 说一件事 | 用自己的话描述：发生了什么、对方最后说了什么、想达到什么 | **不要求导入记录**；信息不足时现场追问，最多 5 轮 | Web |
| J1-A.4 拿建议 | 在工作台看到三档建议 | 从情境中提取原话与诉求，生成三档；页面标注「本次未使用历史记录，个性化程度有限」 | Web |
| J1-A.5 可选沉淀 | 觉得有用 → 选择导入历史记录，让下次更准 | 进入导入页，导入后转入 J1-B | Web |

### 7.2 主旅程 J1-B：进阶使用（有历史记录）

| 阶段 | 用户行为 | 系统响应 | 触点 |
|------|----------|----------|------|
| J1-B.1 进入 | 登录，选择已有档案 | 展示档案与上次会话 | Web |
| J1-B.2 补记录 | 粘贴对方的历史聊天记录 | 自动识别说话人；样本量提示；脱敏检测 | Web |
| J1-B.3 分析 | 查看行为观察集 | 按规范三档输出；标注证据强度与不可推断声明 | Web |
| J1-B.4 描述情境 | 填写三要素（发生了什么 / 对方最后说了什么 / 想达到什么） | 追问最多 2 轮 | Web |
| J1-B.5 模拟 | 试着说出自己想说的话，看 AI 扮演的对方如何回应 | 以对方口吻回应，单次 ≤10 轮；每轮附 1–3 种假设性解读；固定标注 AI 模拟 | Web |
| J1-B.6 建议 | 查看三档建议，选择或要求调整 | 每条带依据、适用前提、风险、失效条件 | Web |
| J1-B.7 反馈 | 标记是否采纳；事后回填对方真实反应 | 写入档案记忆，用于后续建议优化 | Web |

### 7.3 次要旅程 J2：档案与数据管理

| 阶段 | 用户行为 | 系统响应 |
|------|----------|----------|
| J2.1 | 查看 / 修正观察集 | 允许手动修正条目；修正后覆盖模型结论并进记忆 |
| J2.2 | 补充沟通样本 | 增量分析，更新观察集 |
| J2.3 | 删除档案 | 二次确认后**级联物理删除**全部关联数据（含向量） |

### 7.4 页面清单

| # | 页面 | 职责 | 关键交互 |
|---|------|------|---------|
| P-1 | 落地页 | 一句话价值、示例对话预览、登录入口 | 「试试看」直接进登录 |
| P-2 | 登录 / 注册 | 邮箱 + 验证码 | 登录后进档案列表 |
| P-3 | 档案列表 | 我的档案、当前迭代入口 | 卡片式；新建档案为弹窗 |
| P-4 | **工作台**（核心） | 情境 → 模拟 → 建议 的单一页面 | 见下方布局说明 |
| P-5 | 档案详情 | 观察集三档展示、历史会话、修正入口 | 每条观察可展开原句 |
| P-6 | 导入页 | 粘贴记录、说话人标注、样本量提示 | 可手动逐条标注「我 / 对方」 |
| P-7 | 设置 / 隐私 | 数据用途、导出、删除、注销 | 删除需二次确认 |

**工作台布局**（桌面三栏，移动端 Tab 切换）：

```text
┌─────────────────────────────────────────────────────────┐
│ 档案：TA（代号）  │  本次模式：现场描述 / 有历史记录        │
├────────────────┬────────────────────┬───────────────────┤
│ 左：情境        │ 中：三档建议        │ 右：模拟对话       │
│ 发生了什么      │ [稳妥] 文本         │ 你说：…            │
│ 对方最后说      │  依据 / 前提 / 风险  │ TA（AI 模拟）：…   │
│ 我想达到        │ [共情] 文本         │ 解读（假设）：…     │
│ （追问区）      │ [直给] 文本         │ 固定标注：AI 模拟   │
└────────────────┴────────────────────┴───────────────────┘
```

三栏在桌面上同屏，是为了让用户「先看风险再决定要不要演练」，而不是线性地强制走完流程。

## 8. 功能需求

> 优先级：**P0** = MVP 必须；**P1** = MVP 后首个迭代；**P2** = 后续。

### 8.1 账号与隔离（P0）

| # | 需求 | 说明 |
|---|------|------|
| F-01 | 注册 / 登录 / 登出 | 邮箱或手机号 + 验证码；MVP 可先做邮箱 |
| F-02 | 用户数据隔离 | 所有档案、样本、会话、记忆、向量数据按 `userId` 隔离；越权访问返回 404（不泄露资源存在性） |
| F-03 | 会话列表隔离 | 用户只能看到自己的会话；会话归属唯一档案 |
| F-04 | 账号注销 | 注销即级联删除全部数据，含向量索引 |

### 8.2 关系档案（P0）

| # | 需求 | 说明 |
|---|------|------|
| F-05 | 创建档案 | 必填：对方昵称（代号）、关系类型、关系状态；选填：在一起时长 |
| F-06 | 档案数量上限 | MVP 单账号最多 3 个档案（防滥用与成本失控） |
| F-07 | 编辑 / 归档档案 | 归档后不可新建会话，数据保留 |
| F-08 | 删除档案 | 级联删除，二次确认，提示不可恢复 |

### 8.3 沟通样本导入（P0）

| # | 需求 | 说明 |
|---|------|------|
| F-09 | 粘贴文本导入 | 支持直接粘贴微信/其他 IM 的聊天文本；导入为**可选**能力，不阻断首次使用 |
| F-10 | 说话人识别与手动标注 | 自动识别「我 / 对方」；识别失败时切换**气泡式逐条标注**，用户点选每条归属，标注后立即重算，不要求重新上传 |
| F-11 | 样本量双门槛 | **可用门槛 10 轮**：低于 10 轮提示「样本偏少，建议补充」但仍可继续；**趋势门槛 200 条**：低于 200 条只出描述与计数，不出跨时间趋势 |
| F-12 | 敏感信息检测 | 检测手机号、身份证号、地址等，提示脱敏后再提交 |
| F-13 | 长度上限 | 单次导入 ≤ 20,000 字；超出提示分段导入 |
| F-14 | 增量导入 | 后续可追加样本，触发观察集更新，并展示充分性等级变化 |

### 8.4 人格画像 / 行为观察集（P0）

> 分析框架、维度定义、信度门槛与表述规范以 [人格分析知识体系与评估规范](persona-analysis-standard.md) 为唯一依据。本节只写产品侧要求，不重复规范细节；两者冲突时以规范为准。
>
> **唯一例外**：规范 §5 的「双同意」同意规则**不适用本产品**。本产品采用用户单方授权 + 充分告知（见 F-18 与 §10.2）。这是产品决策：亲密关系冲突场景下无法取得对方授权，强制双同意会让核心功能不可用。

| # | 需求 | 说明 |
|---|------|------|
| F-15 | 维度分级实现 | 按规范的 10 个维度实现，分三档：**可输出**（结构量/时间戳统计）、**仅原句**（未过信度门槛）、**仅内部**（无中文效度数据）。不得把后两档包装成结论或分数 |
| F-16 | 结论四段式 | 每条结论必须含：观察（可复算计数或原句）、样本充分性（A/B/C）、理论证据强度（强/中/弱/争/不适用）、不可推断声明。四段缺一即视为违规输出 |
| F-17 | 禁止类型标签 | 不输出人格类型、依恋类型、特质分数、临床或准临床标签；MBTI 类工具既不作为分析框架，也不作为中间映射层 |
| F-18 | 用户授权与告知 | **不要求对方同意**。用户本人完成授权即可使用全部功能。导入页须明确告知「你上传的是他人聊天记录，请确认你有权使用」，用户勾选后记录授权时间与告知文本版本 |
| F-19 | 事实与推断分离 | 爱好、职业、经历、居住地等事实性信息只能来自用户显式陈述，**禁止**由语言风格、词汇偏好、发言时间反推；用户手动修正的维度优先于模型结论 |

**三档维度划分**：

| 档位 | 维度 | 用户看到什么 |
|------|------|-------------|
| 可输出 | 消息节奏与长度分布、会话发起与话轮结构、深夜时段占比 | 计数与分布，标注「行为计数，无人格构念」 |
| 仅原句 | 回应性行为、支持类型配比 | 原句 + 「疑似」标记，不给比例、不给频次 |
| 仅内部 | 延迟耦合、we/I 词频、情绪词密度、聚合 LSM | 不展示，只作追问线索 |

**样本充分性门槛**：A 级（≥2 周且 ≥300 条、≥3 次独立事件、双边记录）才可出趋势与模式；B 级只出描述与计数；C 级只出当次会话分布。信度门槛优先于充分性——编码信度未达标，无论样本多少都只能出原句。

**「重新分析」（原 P1）**：补充样本后重跑，需同时展示充分性等级变化，不得只更新结论。

### 8.5 情境描述（P0）

| # | 需求 | 说明 |
|---|------|------|
| F-20 | 双模式输入 | **现场描述模式**（默认，无历史记录）：用户用自然语言说清发生了什么；**结构化模式**（有历史记录）：填三要素——发生了什么 / 对方最后说了什么 / 你想达到什么 |
| F-21 | 追问机制 | 现场描述模式最多追问 5 轮（因为它是首次价值的主路径）；结构化模式最多 2 轮。追问必须一次只问一个问题，且给出可点击的选项，不让用户面对空白输入框 |
| F-22 | 目标类型 | 和好、表达不满、拒绝、撒娇、道歉、试探态度、结束对话；现场描述模式下由系统从原话中识别，识别不出则列为追问项 |

### 8.6 模拟对话（P0）

| # | 需求 | 说明 |
|---|------|------|
| F-23 | 角色扮演 | AI 以对方口吻回应，语气须贴合**行为观察集**中的语言特征（句长、语气词、表情），不得贴合任何人格类型设定。无历史记录时，用用户描述的对方原话推断语言特征 |
| F-24 | 多解释旁白 | 每轮附 1–3 种可能的解读，全部标注为假设；不得给出单一的「对方真实想法」结论 |
| F-25 | 轮次上限与重试 | 单次模拟 ≤10 轮，到顶提示「已达本次演练上限」，不静默截断；用户可对任一轮重试，重试不消耗轮次 |
| F-26 | 独立上下文 | 模拟对话使用**独立上下文**，不进入建议生成链路；模拟中不得引用对方原话，只能引用观察集条目 |
| F-27 | 模拟标识与跳过 | 界面固定标注「这是 AI 模拟，不代表对方真实想法」；用户可直接要建议，不强制演练 |

### 8.7 回复建议（P0）

> **建议生成不得建立在人格判断上。** 个性化只能来自可复算的行为模式与用户自身的语言习惯，不能来自「他是什么样的人」。这条是硬约束，不是文案风格。

| # | 需求 | 说明 |
|---|------|------|
| F-28 | 三档候选同屏 | 稳妥 / 共情 / 直给一次生成、同时展示；每档必须标注「什么情况下这档会失效」，由用户选，不替用户选 |
| F-29 | 依据可追溯 | 每条建议带四要素：依据（指回具体观察条目）、适用前提、风险提示、失效条件。**依据指不回观察条目的建议直接丢弃**，不展示 |
| F-30 | 风格约束与调节 | 生成前建模用户语言特征（长度均值、语气词、表情、标点）；建议长度 ≤ 用户均值 ×1.5，超限由代码截断重生成。支持「更短 / 更软 / 更直接」重生成，重生成沿用同一依据 |
| F-31 | 一键复制 | 复制纯文本，不含系统标注与依据 |
| F-32 | 越界校验 | 规则层（禁用词、长度、字段完整性）+ 模型层（像不像本人、是否断言动机）双重校验；任一不过即打回重生成，不降级放行 |

#### 8.7.1 建议生成链路

```text
情境 ─┬─ ① 情境解析（结构化，不推断）
      ├─ ② 观察检索（行为模式 / 历史建议 / 真实反应）
      └─ ③ 风格建模（用户自己的语言特征）
              ↓
        ④ 策略合成（一次生成三档，指定行为构件组合）
              ↓
        ⑤ 话术生成（带风格硬约束）
              ↓
        ⑥ 双重校验（规则层 + 模型层）
              ↓
        ⑦ 输出（文本 + 依据 + 前提 + 风险 + 失效条件）
```

| 层 | 做什么 | 不做什么 |
|----|--------|---------|
| ① 情境解析 | 提取对方原话、诉求类型、已知事实、缺失信息 | 不猜动机、不补事实；缺失项 >2 时追问 |
| ② 观察检索 | 取可复算计数与原句：冲突后回复间隔、触发沉默的话类、历史采纳与真实反应 | 不取「他很敏感」这类结论；检索不到就返回空，进入现场描述模式（见 §8.7.3） |
| ③ 风格建模 | 用户历史消息的长度均值、语气词、表情、标点习惯 | 不模仿对方风格 |
| ④ 策略合成 | 按目标与风险组合行为构件，产出三档 | 不按语气软硬分档 |
| ⑤ 话术生成 | 一次生成三条，长度与用词受 ③ 约束 | 不引用 ② 之外的观察 |
| ⑥ 校验 | 禁用词、长度、字段完整性；像不像本人；是否断言动机 | 不做创作优化 |
| ⑦ 输出 | 四要素齐全才展示 | 缺任一要素不展示 |

**行为构件库**（建议的原料，来自规范 §2 的可观测信号）：复述情绪、认可、具体行动承诺、开放式提问、边界表达、事实陈述、具体请求。每档策略由这些构件组合而成。

#### 8.7.2 三档策略定义

| 档位 | 行为构件组合 | 适用 | 失效条件（必须标注） |
|------|-------------|------|---------------------|
| 稳妥 | 认可 + 具体行动承诺，不含边界表达 | 关系紧张、用户不想冲突 | 对方期待明确答复时，会被读作敷衍 |
| 共情 | 复述情绪 + 认可 + 开放式提问 | 对方处于情绪中 | 对方已明确要方案时，会被读作回避 |
| 直给 | 事实陈述 + 边界表达 + 具体请求 | 用户目标明确、关系尚可 | 对方处于高唤醒状态时，可能激化 |

三档必须同屏。分三次生成会造成风格不一致与依据冗余。

#### 8.7.3 能力边界（必须对用户明示）

| 模式 | 可用输入 | 建议质量 | 页面提示 |
|------|---------|---------|---------|
| 有历史记录 | 双方行为模式 + 用户风格 + 历史反馈 | 完整个性化 | 无 |
| 现场描述（无历史） | 本次情境 + 用户原话 + 用户风格 | 通用策略 + 风格贴合 | 「本次未使用历史记录，建议基于你描述的情境，个性化程度有限」 |

两种模式都**不要求对方同意**；用户本人授权即可。模式切换不静默：从「现场描述」补入记录后，页面须提示观察集已更新。

### 8.8 记忆（P0）

| # | 需求 | 说明 |
|---|------|------|
| F-33 | 会话内记忆 | 保留最近 **20 轮**上下文；超出后按「摘要 + 最近 10 轮」压缩，不丢关键事实（对方原话、用户目标） |

### 9.5 技术约束（P0）

| # | 约束 |
|---|------|
| N-23 | 后端使用 **Spring AI** 框架（ChatClient / ChatMemory / VectorStore / Advisor） |
| N-24 | 会话隔离通过对话 ID + 用户 ID 双键实现，禁止仅用对话 ID |
| N-25 | 记忆分层：短期（会话窗口）+ 长期（档案级摘要 + 向量检索） |
| N-26 | 模型供应商可替换（抽象层），不在业务代码中硬编码单一供应商 |
| N-27 | **三层职责分离**：派生量计算（纯代码，无 LLM）→ 观察解释（LLM，受 schema 约束）→ 建议生成（LLM，独立上下文）。禁止让生成建议的模型直接读原始聊天记录做自由分析 |
| N-28 | **结构化输出**：建议集合用固定 schema（record + `BeanOutputConverter`）；`strategy` 限定三枚举值，`basis` / `precondition` / `risk` / `failsWhen` 全部 required，缺字段即反序列化失败并打回 |
| N-29 | **校验隔离**：校验层用独立的 ChatClient 实例与审查员 system prompt，不得与生成共用同一会话，避免自我确认偏差 |
| N-30 | **风格约束可执行**：长度上限由代码计算并在生成后强制截断，不依赖模型自觉遵守 |
| N-31 | **观察数据不进 prompt 原文**：解释层与建议层拿到的是派生量 JSON（计数、分位数、原句切片），不是整段聊天记录。原文仅在用户查看「依据」时按条回读 |
| N-32 | **分级模型**：解释层与建议生成用主模型；校验层用轻量模型（判定任务，不需要强生成能力）。模型档位可配置，不硬编码 |
| N-33 | **缓存策略**：同一档案 + 同一情境哈希 + 同一版本模板，24 小时内命中缓存直接返回，不重复调用；缓存键不含用户正文 |

**分层职责边界**：

| 层 | 技术形态 | 输入 | 输出 | 确定性 |
|----|---------|------|------|--------|
| 派生量计算 | Java 服务（无 LLM） | 原始消息 | 延迟分位数、长度分布、话轮结构、时段占比、词典命中 | 可复算 |
| 观察解释 | ChatClient + schema | 派生量 JSON | 四段式观察结论 | 受约束 |
| 建议生成 | ChatClient + ChatMemory | 情境 + 观察 + 历史反馈 + 风格特征 | 三档建议 + 四要素 | 受约束 |
| 校验 | 独立 ChatClient + 规则引擎 | 生成结果 | 通过 / 打回原因 | 双重 |

## 10. 数据与合规

### 10.1 涉及的个人信息

| 数据 | 主体 | 敏感级别 | 处理 |
|------|------|----------|------|
| 账号（邮箱/手机） | P1 | 一般 | 加密存储 |
| 沟通记录原文 | P1 + **P2（第三人）** | **敏感** | 加密存储；可删除 |
| 人格画像 | P2 | **敏感（推断数据）** | 加密存储；标注推断性质 |
| 会话与建议 | P1 | 敏感 | 加密存储 |
| 使用日志 | P1 | 一般 | 脱敏；不含正文 |

### 10.2 合规要点（中国境内）

- **个人信息保护法**：处理第三人（P2）信息需具备合法性基础。本产品采用**用户单方授权 + 充分告知**，不要求对方同意：
  ① 导入页明确告知「你上传的是他人聊天记录，请确认你有权使用」；
  ② 用户勾选确认，记录授权时间与告知文本版本；
  ③ 提供一键删除、导出通道；
  ④ 不采集对方真实姓名、联系方式，引导使用代号。
  **风险边界**：单方授权不等同于取得对方同意，该风险在告知页明示由用户承担；产品侧不做进一步验证。告知文案须法务审核。
- **生成式 AI 服务管理**：模型服务需选用已完成备案的供应商；生成内容须有安全过滤。
- **未成年人**：注册环节做年龄确认；不面向未成年人提供服务。
- **数据出境**：若使用境外模型 API，需评估是否构成数据出境。

> 合规结论需法务确认，本 PRD 仅列出约束项。
