# 系统画像变更约束

画像（`architecture/system-landscape.md`）是项目层事实与微服务技术选型的唯一定义处。通用 `skills/` 与通用 `rules/` 直接按编号读取画像、不复制具体项目事实；因此画像变更时，只需按本表同步**受选型影响的条件规则与项目级配置**，避免静默漂移。

## 一、同步对照

### 1.1 项目事实变更

| 画像变更 | 需同步的派生项 |
|----------|---------------|
| §二 服务清单（服务名/数量/数据归属） | 项目根 `AGENTS.md` 服务摘要表；`hooks/bugfix-protect-common.sh` 保护路径（若公共库/`*-api` 变更）；Golden（按需） |
| §3.6 跨服务通信矩阵 | 仅使用期消费（详设调用关系、单服务 `*IT` 下游模拟清单），无需改动 Rule |
| §3.7 公共库锚点与错误码号段 | `rules/exception-and-result.md` 项目实现速查节（若公共库 API 签名变更） |
| §六 URL 前缀 | 仅使用期消费（详设与编码读画像 §六），无需改动通用 Rule |
| §二 业务域大幅调整 | 词表同步；Golden 按需重写 |
| §4.3.4 测试账号 / §四 外部系统 | 仅使用期消费（造数、集成 Mock 边界），无需改动 Rule |

### 1.2 微服务技术选型占位拍板同步（画像 §5.4）

当画像 §5.4 中的任意项从 `[TBD]` 拍板定稿或发生切换时，按此表检查并同步对应条件规则与配置：

| 占位编号 | 选型项 | 需检查 / 同步的项 |
|----------|--------|-------------------|
| **P-1** | 仓库组织模式（单仓多服务 / 多仓） | 项目根 `AGENTS.md`（若选多仓，确认总文档仓、契约同步与各仓校验路径已落文档） |
| **P-2** | 服务间同步调用协议（OpenFeign / Dubbo / gRPC 等） | 使用期各 Skill 直接读取画像 P-2；若需补充项目级框架细则，记录到画像 §3.6 或新增项目补充 Rule |
| **P-3** | 数据库访问框架（ORM） | 选 MyBatis → 启用 `rules/mybatis-conventions.md`；选 JPA/jOOQ 等 → 删除并替换为对应 ORM 持久化 Rule |
| **P-4** | 响应格式与跨服务错误码规则 | 画像 §3.7、`rules/exception-and-result.md` 项目实现速查节 |
| **P-5** | 内部接口防外泄与服务间鉴权 | 项目根 `AGENTS.md` 摘要；细则由各 Skill 直接读画像 §5.4 P-5 |
| **P-6** | 公共库边界（`*-common`） | 项目根 `AGENTS.md`、`hooks/bugfix-protect-common.sh` 保护路径 |
| **E-1 ~ E-7** | 服务注册配置 / 异步 MQ / 跨服务一致性 / 事件契约 / 契约测试 / 多实例定时调度 / 链路追踪 | 拍板结论直接写入画像 §5.4 即可被各 Skill 消费；仅当项目需要补充团队专属编码细则时新增项目 Rule |

## 二、变更记录

画像末尾「变更记录」表的**影响面**列标注本次变更需同步哪些项（无影响写「无」）；未标注时按上表推导。

## 三、验证

同步后跑：

- `bash scripts/validate-skills.sh --quiet-tick`（硬断链与画像小节编号检查）

## 四、与单点维护的关系

项目事实与微服务技术选型只写画像（见 [AGENTS.md](../../AGENTS.md)）。通用 `skills/` 与通用 `rules/` 引用画像而不硬编码项目值，因此日常画像变更**不需要批量修改几十个 Skill 文件**。画像被 Skill 与校验器引用的小节编号（`§3.7` / `§4.3.4` / `§4.7` / `§5.4`）不得改动，编号漂移锚点即断。
