# 系统画像变更约束

画像（`architecture/system-landscape.md`）是项目层事实的唯一定义处。它的变更会传导到已生成的 `skills/`、`rules/` 与 Golden——**改动画像就欠一次回刷**：漏刷不会报错，只会静默漂移。

## 一、回刷对照

| 画像变更 | 需回刷的派生项 |
|----------|---------------|
| §二 模块清单（模块名/数量） | `skills/`、`rules/` 中的模块名引用（锚点替换的模块映射结果）；Golden 中的模块名 |
| §3.7 错误码号段 | `skills/`、`rules/` 中的号段描述与 `*ErrorCode` 示例 |
| §六 URL 前缀 | `skills/`、`rules/` 中的 URL 示例 |
| §二 业务域（域数量/命名） | Golden 全族重写；词表同步 |
| §4.3.4 测试账号 / §四 外部系统 | 仅使用期消费（造数、集成 Mock 边界），无需回刷 |

## 二、变更记录

画像末尾「变更记录」表的**影响面**列标注本次变更需回刷哪些派生项（无影响写「无」）；未标注时按上表推导。

## 三、验证

回刷后：

- 跑 `bash scripts/validate-skills.sh`（硬断链检查）
- 跑 [MIGRATION.md](../MIGRATION.md) §一.3 的残留检查（用映射表中未被目标选用的旧值构造 grep）

## 四、与单点维护的关系

项目事实只写画像（见 [AGENTS.md](../../AGENTS.md)）；本约束是「单点维护」的操作细则——Skill 与 Rule 引用画像而不复制正文，所以画像变更只需按上表回刷派生引用，不必追着十几个文件改正文。画像被 Skill 引用的小节编号（§3.7 / §4.3.4 / §4.7）不得改动，编号漂移锚点即断。
