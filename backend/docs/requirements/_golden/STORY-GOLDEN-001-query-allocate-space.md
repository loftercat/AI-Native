## 1. 用户故事

作为 **车主**，我想 **根据目的地或车场查询可预约车位、查看收费说明，并由系统推荐一个最近的可预约车位**，以便 **在确认下单前知道停哪里、费用大概多少、减少找位时间**。

## 2. 范围

### 2.1 目标

- C 端经 `booking-bff-app` 提供：
  - **按目的地/关键词查支持预约的车场**（列表摘要）；
  - **按车场 ID 查详情**（名称、地址、**车场停车费说明**、**预约服务费说明**）；
  - **按车场 + 预约时段查可售车位概况**；
  - **按规则自动推荐一个车位**（车位编号、区域、车场、时段、**距最近电梯步行距离**等摘要）。
- `booking-inventory` 承担可售判断、推荐逻辑及车场/费率只读聚合；仅 **空闲** 车位参与推荐（见 BR-01）。
- 本 Story 为管道型预约旅程的 **「准备」卡**；点击「预约车位」后的下单、锁定、支付在 **后续 Story**（范本中记为 STORY-2026-S01-002）。

### 2.2 非目标

- 创建预约单、车位 **锁定中** 持久化、支付订金、预约成功页（见后续下单 Story）。
- C 端 **页面与地图 UI**（另仓）：默认展示用户位置地图、地图缩放、语音输入地址、第三方地图「导航到位」、室内导航与「导航到梯」路径规划。
- 有 **进行中预约单** 时的首页分支（原型 `存在进行中的预约单.html`；见后续 Story）。
- 扫码预约、代客预约入口（后续 Story）。
- 预约规则全文（5 分钟免费取消、黑名单等）的 **配置与变更**（HLD S-12）；本 Story 仅 **只读展示** 与费率绑定的规则摘要字段 `[AI推断]`，若无则返回空。
- 按经纬度/GIS 逆地理匹配车场（V1 关键词匹配名称/地址）；蓝牙电梯硬件与安装（仅消费主数据中的电梯坐标/距离用于 BR-02）。

### 2.3 校验职责

| 层级 | 职责 |
|------|------|
| **BFF** | 鉴权（车主身份）、请求参数格式（关键词非空、时段起止合法、车场 ID 存在性由下游返回业务错误） |
| **inventory 域** | 车场是否开放预约、时段是否在可预约时间窗内、车位是否空闲、推荐算法、费率说明只读组装 |
| **前端（另仓）** | 地图与定位、目的地/语音输入控件、列表与详情页布局、展示 API 返回的收费文案 |

## 3. 业务规则（BR）

| 编号 | 规则 | 备注 |
|------|------|------|
| BR-01 | 仅 **空闲** 状态的车位可参与可售查询与自动推荐；锁定中、已预约、占用、维护中均不可推荐 | 对齐词表 §3.2 车位状态 |
| BR-02 | **自动分配** 在可售车位集合中，优先推荐距最近电梯 **步行时间 ≤ 90 秒**（或直线距离 ≤ 100 m）的车位；若多个满足则取步行时间最短者；响应须含 **距电梯步行距离（米）** | 原型「自动分配车位」；阈值 `[AI推断]` 可配置 |
| BR-03 | 仅 **已开启预约服务** 的车场出现在目的地匹配结果中 | 车场主数据 `bookingEnabled=true` |
| BR-04 | 用户请求的 **预约时段** 须落在车场可预约时间窗内；否则不可推荐 | MVP 可与营业时间一致 `[AI推断]` |
| BR-05 | 车场详情须返回 **车场停车费说明**、**预约服务费说明** 两段可读文案（与原型选中大厦后展示一致）；数据来源于车场主数据及预约服务费配置 | 原型「收费详情」 |

## 4. 验收标准（AC）

> 失败类 `Then` 指 API 响应 `Result` 中 `code !== 200` 且 `message` 为下列文案（或等价明确文案）。HTTP 层可为 200。

### AC-01：按目的地查询支持预约的车场（影响层：BFF、inventory）

- **Given** 存在至少 1 个 `bookingEnabled=true` 的车场，其地址或名称与关键词「万象城」匹配
- **When** 车主调用 `GET /api/v1/booking/app/lots?keyword=万象城`
- **Then** 返回车场列表，每项含 `lotId`、名称、地址、`bookingEnabled=true`；列表按与关键词相关度排序 `[AI推断]`

### AC-02：目的地无匹配车场（影响层：BFF、inventory）

- **Given** 不存在与关键词「不存在的大厦XYZ」匹配且支持预约的车场
- **When** 车主调用 `GET /api/v1/booking/app/lots?keyword=不存在的大厦XYZ`
- **Then** `message` 为 **「很抱歉，此大厦暂无车位预约服务」**，返回空列表

### AC-03：查询车场详情含收费说明（影响层：BFF、inventory）

- **Given** 车场 L1（`bookingEnabled=true`）已配置停车费说明与预约服务费说明（与原型「华润置地大厦E座」示例等价）
- **When** 车主调用 `GET /api/v1/booking/app/lots/{lotId}`，`lotId=L1`
- **Then** 返回名称、地址、`bookingEnabled`、**`parkingFeeDescription`**（含「首小时」「24小时最高」等关键语义）、**`bookingServiceFeeDescription`**（含「首2小时」「超时」等关键语义）；**不** 返回订金金额与支付参数

### AC-04：查询指定车场在时段内的可售概况（影响层：BFF、inventory）

- **Given** 车场 L1 在 2026-08-01 10:00–12:00 有 3 个 **空闲** 车位、1 个 **占用** 车位
- **When** 车主调用 `GET /api/v1/booking/app/lots/{lotId}/spaces/available`，传入 `lotId=L1`、`startTime=2026-08-01T10:00:00`、`endTime=2026-08-01T12:00:00`
- **Then** 返回 `availableCount=3`，且 **不** 将占用车位计入可售数

### AC-05：自动推荐一个最近可预约车位（影响层：BFF、inventory）

- **Given** 车场 L1、时段 2026-08-01 10:00–12:00 内存在多个 **空闲** 车位，其中 S-101 距电梯最近且满足 BR-02
- **When** 车主调用 `POST /api/v1/booking/app/reservations/allocate`，传入 `lotId`、时段、车牌（可选，用于后续下单预填）
- **Then** 返回 `spaceId=S-101`、车位编号、区域名称、车场名称、预约时段、**`walkDistanceToElevatorMeters`**（正整数）；**不** 创建预约单，**不** 将车位改为锁定中

### AC-06：时段内无可用车位（影响层：BFF、inventory）

- **Given** 车场 L1 在请求时段内 **空闲** 车位数为 0
- **When** 车主调用自动分配接口
- **Then** `message` 为 **「无可预约的车位」**

### AC-07：预约时段不合法（影响层：BFF）

- **Given** 车主已登录
- **When** 调用可售查询或自动分配接口，且 `endTime` 早于或等于 `startTime`
- **Then** `message` 为 **「预约结束时间须晚于开始时间」**

### AC-08：车场未开放预约（影响层：BFF、inventory）

- **Given** 车场 L2 的 `bookingEnabled=false`
- **When** 车主对 L2 发起车场详情、可售查询或自动分配
- **Then** `message` 为 **「该车场暂不支持预约」**

### AC-09：车场不存在（影响层：BFF、inventory）

- **Given** 不存在 `lotId=999999`
- **When** 车主调用车场详情或可售查询，`lotId=999999`
- **Then** `message` 为 **「车场不存在」**

## 6. 测试关注点

- 并发：多用户同时推荐同一 **空闲** 车位时，本 Story **不锁定**，可能推荐给多人；防超卖在后续下单 Story 验证。
- 推荐算法：BR-02 边界（恰好 100 m、等距多车位）需单元测试覆盖。
- 车场不存在 vs 不支持预约 vs 无匹配关键词 — 错误文案与 `code` 稳定（AC-02 / AC-08 / AC-09）。
- 费率说明字段为空时：AC-03 返回空字符串或省略字段的策略需在详设约定，勿 500。
