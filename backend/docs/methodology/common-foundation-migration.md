# 项目公共基础库登记与适配指南

> **定位**：一次性接入指南（配合 `backend/MIGRATION.md` §一.2 与 §一.3）。
> 因为本模板的 `skills/` 与通用 `rules/` 已彻底去源项目化、不再硬编码特定公司公共库，接入项目时**无需做全局字符串批量替换**——只需由 AI 从目标项目构建文件与公共库源码中提取真实 API 契约，登记到 **2 个单点位置**（画像 `§3.7` + `rules/exception-and-result.md`「项目实现速查」）即可。

---

## 一、AI 自动采集清单（不要求用户一次手填）

数据来源优先级：

1. 目标项目构建文件：`pom.xml` / parent POM → 公共库 Maven 坐标、版本属性、模块路径。
2. 公共库源码 / API 文档 / jar：统一响应体、业务异常、错误码接口、分页、全局异常处理器、ID 生成器的真实类与方法签名。
3. 用户拍板：画像 §5.4 **P-4**（对外/对内响应形态、跨服务错误码透传或映射策略）与各微服务错误码号段分配。

| 信息 | 优先来源 | 缺失时 |
|------|----------|--------|
| 对外/对内响应形态与跨服务错误码策略 | 用户拍板（画像 §5.4 P-4） | **阻断**：无法确定接口契约与 Feign/RPC 错误解包写法 |
| 公共库坐标、版本属性与包根 | `pom.xml` / 源码 import（若项目自研封装则填本仓公共模块） | **阻断**：无法生成正确依赖与 import |
| 统一响应体 API 与成功判据（若采用包装体） | 公共库源码 / 文档 | **阻断**：无法判断 `code === ?` 与成功/失败构造方式 |
| 业务异常与错误码接口（`BizException` / `ErrorCode`） | 公共库源码 / 文档 | **阻断**：生成代码无法编译 |
| 分页请求/响应对象（如 `PageQuery` / `PageResult`） | 公共库源码 / 文档 | 记录待补或按项目约定写明 |
| 主键生成器（若画像 P-3 选用应用侧 ID 生成） | 公共库源码 / 文档 | **阻断**：写路径无法生成主键 |
| 微服务错误码号段分配表 | 现有枚举扫描 / 用户拍板 | **阻断**：OpenAPI examples 与 `bugfix` 责任定位无依据 |
| 全局异常处理与远程解包组件行为 | 公共库源码 / 文档 | 影响详设与单测断言 |

---

## 二、两步登记流程

### 步骤 1：提取与确认（人工介入点）

AI 扫描目标项目构建文件与公共库源码，整理出一份《公共基础库与错误码登记草案》（含坐标、核心类签名、成功判据、跨服务错误传播规则、各微服务号段表），标出缺失项交用户一次性确认。

### 步骤 2：写入两处单点位置

确认后，AI 只更新以下两处文件（不碰任何通用 `skills/` 正文）：

1. **`AI-Native/backend/architecture/system-landscape.md` §3.7 与 §5.4 P-4**：
   - 填写对外/对内响应形态、跨服务错误码策略、公共基础库锚点表与微服务错误码号段分配表。
2. **`AI-Native/backend/rules/exception-and-result.md`「三、项目实现速查」**：
   - 将模板中的占位速查表替换为本项目真实公共库坐标、类全限定名、构造器/静态方法速查与最小代码示例，供 AI 编码直接照抄、防止造同名轮子。

---

## 三、验收

1. 跑 `bash AI-Native/backend/scripts/validate-skills.sh --quiet-tick` → **PASSED**。
2. 核对 `system-landscape.md` §3.7、`rules/exception-and-result.md`「项目实现速查」与项目根 `AGENTS.md` 三者无矛盾、无未填占位符 `{company-common}` 残留。
3. 走通一张真实 Story（`detail-design → feature-coding`），确认生成的 import、响应封装、错误码号段与全局异常处理可直接通过编译与单测。
