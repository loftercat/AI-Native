# 幂等性设计实践指南（Java 微服务）

> **L1 静态层上下文资产**：`detail-design` 步骤 6 在 AC/BR 出现创建、提交、回调、重复通知、重试、防重复、MQ 消费等关键词时加载本指南。
> 异常与错误码见 [exception-and-result.md](./exception-and-result.md)；专项场景见 [special-scenarios.md](../skills/detail-design/references/special-scenarios.md)。

## 一、什么是幂等性

**同一操作执行一次和执行多次，对系统状态的影响完全相同。**

重复请求在微服务架构下不可避免：用户双击、前端超时重试、API 网关重试、外部回调重复通知、**服务间远程调用超时重试**、**异步消息（MQ）重复投递**。

---

## 二、适用场景

| 场景 | 触发原因 | 微服务必查要点 |
|------|---------|----------------|
| 前端重复提交 | 双击、刷新 | 敏感写接口评估幂等键 |
| 接口超时重试 | 客户端 / 网关重试 | BFF 写操作 POST |
| 外部回调重复 | 外部系统 at-least-once 通知 | 回调业务单号唯一约束 + 状态机条件更新 |
| 服务间远程重试 | 网络超时 / 客户端重试（按画像 §5.4 P-2） | 被调微服务内部写接口须支持幂等键或条件更新 |
| MQ 重复消费 | 异步消息至少一次投递（按画像 §5.4 E-2） | **微服务必查**：消费侧必须做业务键唯一约束 / 幂等消费表 / 状态机条件更新去重 |
| 定时任务重跑 | 多副本并发或失败重试（见 [scheduled-task-guide.md](./scheduled-task-guide.md)） | 多实例锁 + 单条处理条件更新 |

## 三、HTTP 方法的天然幂等性

| 方法 | 天然幂等？ | 说明 |
|------|----------|------|
| GET | 是 | 只读 |
| PUT | 是 | 全量替换 |
| DELETE | 是 | 最终「已删除」 |
| PATCH | 不一定 | 「设为某值」幂等；「增量加减」非幂等 |
| **POST** | **否** | 创建/动作类 → **须评估幂等设计** |

对外与内部非查询型写操作（POST）在详设 §5 须明确幂等方案。

## 四、四大幂等方案选型

### 方案 A：幂等键 + 分布式缓存（敏感写操作，按需）

**适用**：资金、资源锁定、单据创建、不可逆状态推进等重复不可接受的写接口。
**不适用**：普通配置或低价值草稿（避免全站盲目套用增加复杂度）。

```text
请求携带 X-Idempotency-Key
  → 缓存 SETNX idempotency:{key} processing EX {TTL}
      ├─ 成功：执行业务 → 缓存响应 → 返回
      └─ 已存在：已完成后返回缓存结果；仍在 processing 则返回「处理中」业务码
```

| 场景 | Key 构造模式 |
|------|-------------|
| 客户端表单 | UUID（页面初始化生成） |
| 业务单据动作 | `{domain}:{entityId}:{action}` |
| 外部回调 | `{externalSystem}:notify:{externalTxnId}` |
| 服务间调用 / MQ | `{sourceService}:{eventOrTxnId}` |

### 方案 B：数据库唯一索引（创建类 / 消费去重首选）

对天然唯一业务键（如 `uk_biz_no`、`uk_event_id`）建数据库唯一索引；重复写入触发唯一键冲突时捕获并按幂等成功或既定业务码返回（避免纯靠先查后插产生并发竞态）。

### 方案 C：专用幂等记录表（MQ 消费 / 回调通用）

与业务写操作在**同一个本服务本地事务**内向 `idempotent_record(biz_key UNIQUE, status, created_at)` 插入记录：插入冲突即视为已处理直接 ACK，确保消息重投零副作用。

### 方案 D：状态机条件更新（状态迁移首选）

写库 SQL 显式携带前置状态条件：

```sql
UPDATE {table_name}
SET status = #{targetStatus}, updated_at = NOW()
WHERE id = #{id} AND status = #{expectedStatus};
-- 软删支再加 AND deleted = 0；状态作废支不加
```

通过受影响行数 `affectedRows == 1` 判定是否由本次请求完成状态迁移；`0` 行时查询当前状态区分「已达目标态（幂等返回）」与「非法前置状态（抛业务异常）」。

## 五、设计 Checklist（详设必查）

- [ ] 敏感写 POST / 服务间写接口 / 外部回调 / MQ 消费者均已明确幂等方案（A/B/C/D 之一或组合）
- [ ] 唯一键、幂等表或条件更新均落在本服务独立数据库内，无跨库事务假设
- [ ] 并发重复请求行为（返回相同结果 / 返回处理中 / 抛明确业务码）已在 AC 或详设写清
